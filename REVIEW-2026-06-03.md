# Marklee — Deep Review & Roadmap (2026-06-03)

## 1. Honest verdict

Marklee is genuinely good at two hard things, and most products that attempt either get them wrong. First, its **edit-tolerant anchoring kernel is real engineering** — `src/ai/resolver.js` `findInFlat` + `normalizeWithMap` (resolver.js:64, :150) is a 6-tier fuzzy matcher with an `origOf[]` offset map that lets it match in heavily-normalized space yet return exact source coordinates. That is the part most quote-grounding code gets wrong, and it is the basis for the only defensible commercial story (LLM citation grounding, SPEC.md:12). Second, the **model-free figure detector** (`figure-detect.js` `detectImageXObjectsForPage` at :219) reconstructs figure bounding boxes from the PDF operator list with zero AI calls and zero model license. The visual layer is also far above the norm for a no-framework app: 13 art-directed themes, the sticker-peel metaphor (styles.css:1755), and the blurred group overlay with flowing connectors (styles.css:3479). What holds it back from "masterpiece" is concentrated in three places: (1) `src/main.js` is a **7091-line unstructured monolith** with ~25 mutable globals, one shared `state` object, no reactive layer, no types, no linter, and zero controller test coverage — every change is grep-and-pray; (2) the **product is half-shipped across platforms** — unsigned/un-notarized desktop binary, no release CI, Chromium-only web, Safari/Firefox hit a throwing stub (main.js:79-82, opfs-store.js); and (3) the **core interaction loop is mute** — manual snippet capture produces no confirmation feedback (pulseSnippet exists at main.js:5301 but is never called on user capture), and Markdown/text docs render light-on-light in every dark theme (styles.css:4674). The bones are excellent; the connective tissue and the last mile are not.

## 2. The core tension

Marklee's identity is "no server, no account, ever" — stated verbatim in at least six places (SPEC.md:16, SPEC.md:515, README.md:3, landing/index.html:521, :574, :631). This is load-bearing for adoption with the exact privacy-sensitive audience the product courts, and it directly conflicts with any payment/SSO plan.

**Recommended resolution — do not pretend the tension away, scope it precisely:**

- **The free, local desktop app never contacts a server.** No account, no telemetry, no crash-reporting, no silent update-ping. This becomes a *verifiable, code-enforced invariant* (the CSP `connect-src` allowlist at tauri.conf.json:25 is the enforcement mechanism — keep it minimal), not a softened slogan. This is more credible than the current absolutist wording, which you are about to break the moment any paid endpoint ships.
- **Monetize only what local-first physically cannot do.** There are exactly three server-shaped things: (a) AI compute you didn't BYO-key for, (b) a *trusted shared* audit/verify system-of-record (you cannot trust a log the annotator can rewrite on their own disk), and (c) team workspaces/SSO. Everything else the local app already does.
- **Identity lives as a license token in the existing encrypted secrets store** (secrets.rs:164-206 `set_provider_key`/`get_provider_key` are provider-generic — store a `marklee-license` token verbatim, zero new Rust crypto). A paying user pastes one token exactly like they paste an API key today. The local app never logs in. An expired/absent token degrades *silently* to the full free app — no nag, no error dialog.
- **Edit the brand line** (the six locations above) from `"no server, no account, ever"` to: *"The free app never contacts a server — no account, no telemetry, no phone-home. Paid features are the only thing that ever leaves your machine, and only when you enable them."*

The stress-test surfaced one specific dishonesty to avoid: the existing permalink already embeds the full anchor payload in the URL (marklee-permalink.js:30-60), so a colleague *without the file* can already resolve a shared snippet with zero server. Hosted permalinks add only short/vanity links + revocation — sell them as that, never imply sharing requires Pro.

## 3. Goal-by-goal plan

### 3a. Artistic & Fun (goal #1)

**Verdict: strong foundation, mute core loop.** The peak moments (group overlay, sticker peel, hover-connector beam at main.js:4030) are genuinely crafted, but the most-repeated action — capturing a snippet — has no payoff, and half the supported document kinds break the theme system.

**Highest-leverage moves:**
- **Make capture feel like a snap.** Text-select (main.js:4561), flow (4595), and region capture (3851) push to `state.snippets` and re-render but never pulse the new card. Call `pulseSnippet(snip.id)` + `scrollIntoView` on every manual capture, and add a one-shot highlighter "lay-down" animation at the selection rect (`@keyframes` with `clip-path: inset(0 100% 0 0)` → `inset(0)`, plus `mix-blend-mode: multiply` so overlapping highlights deepen like real marker). Reuses existing keyframes. **(S)**
- **Token-ize `.flow-doc`** (styles.css:4674-4742). It hardcodes `#fbf9f3` bg / `#1f1f1f` text, so Markdown/txt/docx render near-invisible in dark/midnight/terminal/steampunk. Replace with `--pane-bg`/`--pane-fg`/`--pane-panel`/`--pane-border`. Same fix in the HTML-export template (~main.js:7075). **(S)**
- **Add `prefers-reduced-motion`** — there is none anywhere in the 4921-line stylesheet, yet 5 infinite loops run (styles.css:2327, 3142, 3591, 3648, 3675). One media block. Accessibility + "calm tool" win. **(S)**
- **Fix the cold open.** `renderSnippets` (main.js:4627) has no empty state for the primary case (doc open, zero snippets); `#viewer-empty` (index.html:71) is one dim line. Add a teaching empty-state ("Select text to make your first snippet — or press R to clip a region") and a one-time drag-select coachmark. **(M)**
- **Expose + color-correct the Map view.** `switchView` fully supports `view==='map'` (main.js:5362-5396) but there is no tab button (index.html:139-140) — the most explorable surface is unreachable. Add the tab, and fix map-view.js:190's bespoke hash-based `groupColor` (it shows *different* colors than every other surface) by injecting the shared palette. **(M)**
- **Redesign the lineage graph as the signature centerpiece.** It is the intellectual core ("PageRank for annotations") but the least-crafted surface — generic boxes-and-arrows (map-view.js:30-160) next to a group overlay with flowing connectors. Size nodes by MarkRank, group-color as glow halo, bezier edges with the `link-flow` beam, dot-grid paper background. This is also the shareable hero shot the landing page lacks. **(L)**

### 3b. Engineering Masterpiece (goal #2)

**Verdict: clean at the edges, structurally fragile at the center.** The extracted modules (persistence.js, ai/*, storage/*, view modules) are clean, dependency-injected, single-responsibility units with a real test seam. The 7091-line `main.js` is the opposite and is the dominant obstacle to this goal.

**Highest-leverage moves:**
- **Decompose `main.js` incrementally** using the *same* `setup({...})` DI pattern already proven by persistence.js/ai-panel.js/clipboard.js. Self-contained first cuts: `viewer-gestures.js` (the 4 overlapping mousedown handlers at 3763/3860/3928/4495), `ai-orchestration.js` (1175-2120), `find-search.js` (2467-2645), `workspaces.js` (385-705), `theme.js` (513-2322), `snippet-render.js`. Target: `main.js` becomes a <500-line boot/wiring file. Do it module-by-module behind DI so nothing breaks at once. **(XL)**
- **Add a ~50-line observable store.** Today `state` is mutated directly at 77+ sites and correctness depends on remembering to call the right repaint (`refreshActiveView` 32×, `applyAllHighlights` 27×). The defensive chaining of all three repaints together *is* the symptom. Wrap `state` so mutations notify subscribers keyed to slices. Kills the "mutate-and-forget-to-repaint" bug class. No framework needed. **(L)**
- **Consolidate the gesture layer** into one Pointer Events state machine (`IDLE → RECT_DRAWING / TEXT_DRAGGING / PRESS_PENDING`). The four mousedown handlers coordinate only through shared flags (`rectDraw`, `_textDragAnchor`, `hoverSnippetId`, `state.tool`) with load-order-dependent execution — the highest pointer-regression risk *and* a direct touch/web porting hazard. Pointer Events serve touch/web from the same path. **(L)**
- **Add static analysis at near-zero cost.** No tsconfig/jsconfig/eslint/prettier exist. Add `jsconfig.json` with `checkJs` + JSDoc (keeps `.js`, gets `tsc --noEmit` in CI), ESLint flat config (`no-unused-vars` catches the dead code: `autoDetectStore`, `OpfsStore`, the disabled ONNX cache), Prettier. **(M)**
- **Establish a controller test seam.** Tests cover only 4 pure functions. Add a Playwright/Tauri smoke suite for the critical flows (open, rect-draw, AI accept, persist+reload, theme switch) in CI; this is the only realistic way to protect a refactor of this size. **(L)**
- **Extract one `colors.js`** (palette + `groupColor`/`lighten`/`darken`/`hex↔hsl`) and delete the duplicated/divergent implementations in main.js (5186) and map-view.js (190). **(S)**

**Correctness defects worth fixing regardless of refactor:**
- **`findInFlat` anchors to the first match with no uniqueness check** (resolver.js:64-133). SPEC §4 requires *exactly one* occurrence; captured context fields are never used to disambiguate. Repeated boilerplate quotes anchor to the wrong instance — this breaks the citation-grounding claim that is the whole commercial wedge. Scan for a second occurrence, disambiguate by context, demote to orphan if still ambiguous. Then reuse `findInFlat` as the *single* anchoring kernel (today the weaker viewer matcher relocates saved snippets — the best matcher isn't reused). **(M)**
- **Normalizer drift:** three disagreeing normalizers (flow-viewer.normalizeText does *no* Unicode normalize, resolver uses NFC + hand-rolled ligatures, SPEC §4.1 mandates NFKC). Pick one canonical form. **(M)**

### 3c. Cross-Platform & Web (goal #3)

**Verdict: a macOS desktop app + a Chromium-only demo, walled off from everything else.** This is the least launch-ready dimension.

**Highest-leverage moves (in order):**
- **Build signing/notarization + release CI.** No signing config exists anywhere (tauri.conf.json:28-42, grep for `TAURI_SIGNING_*` returns nothing); README documents an `xattr` workaround confirming the DMG is unsigned. CI only runs `bun test` + `vite build` on ubuntu — it never builds a desktop bundle. Add Apple Developer ID + notarytool, Windows Authenticode, the Tauri updater plugin, and a `tauri-action` matrix (macos/windows/linux) gated on tags. **This is the gate between "local dev build" and any shippable product, and an unsigned binary is an instant trust failure for the legal/compliance buyer.** **(L)**
- **Make Chromium web first-class.** Persist the FSA directory handle to IndexedDB (it's structured-cloneable) and `handle.requestPermission()` on boot; stop the unconditional workspace wipe at main.js:389-393. Call `navigator.storage.persist()`. Today every reload forces a folder re-pick (fsa-store.js:48-58), which makes the web build feel like a throwaway demo. **(M)**
- **Feature-gate backend selection.** main.js:79-82 hardcodes `IS_TAURI ? TauriStore : FsaStore` with no feature check, so Safari/Firefox (30%+ of browser share) load the full app and `pickRoot()` throws (fsa-store.js:49). The well-designed `autoDetectStore()` (store.js:67-81) is dead code. Short term: gate on `showDirectoryPicker` presence and show an honest "use Chrome/Edge or desktop" state. Real fix: implement `OpfsStore` over `navigator.storage.getDirectory()` (it's a pure throwing stub today, opfs-store.js:11-31). **(L)**
- **Gate every Tauri `invoke` behind `IS_TAURI`** with graceful web degradation: keep the model-free figure detector working in-browser; disable ONNX/Docling/Ollama/arboard paths (onnx-layout.js:41, clipboard.js:36) instead of throwing; wire `store.capabilities()` into the UI so features hide rather than error. **(L)**
- **Fix the confirmed CSP/Gemini bug** independently of everything: tauri.conf.json:25 lacks `generativelanguage.googleapis.com`, so Gemini (gemini.js:161 direct fetch) is silently blocked in any packaged desktop build. Keep desktop BYO-key Gemini first-class — do not fold this fix into "web requires Managed AI." **(S)**
- **Fix the namespace inconsistency before broadening distribution:** `~/.pdf-annotator` (lib.rs:309) vs `~/.marklee` (lib.rs:511) vs identifier `com.markleeapp.desktop` vs IndexedDB name `pdf-annotator` (fsa-store.js:34). Pick one, ship a one-time migration. Paid sync data landing in the wrong dir is an unrecoverable solo-dev support nightmare. **(S)**
- **Mobile: defer.** No iOS/Android project exists; the desktop-bound deps (ort, python3 Docling, ollama, arboard) plus a fixed `100vw/100vh` px grid make it an XL track. Do not block web/desktop launch on it. **(XL, Later)**

### 3d. Pricing + Payments + SSO (goal #4) — with stress-test folded in

**Verdict: sound architecture, wrong emphasis.** The plan correctly keeps the local core free and account-free, and the client integration cost is genuinely small (verified: secrets.rs is provider-generic, the provider abstraction is uniform so a "managed" provider is a one-file add). But three stress-test lenses converged on the same correction:

**The willingness-to-pay is mis-placed.** The plan names the verify/audit pipeline as its "strongest commercial wedge" (SPEC.md:12) but buries it in Team/Enterprise behind SSO — *while that feature already runs free and offline in the CLI* (ai-batch.mjs drops hallucinated quotes to "orphan"). Meanwhile the Pro tier is built on weak hooks: Managed AI asks the privacy-conscious BYO-key crowd to abandon their own cheaper keys; hosted permalinks duplicate what the URL payload already does; and **ISO-32000 export is a one-time-value, server-less feature being sold as a subscription — that violates the "charge only for server-shaped work" rule and reads as paywalling users out of their own data. Ship export FREE.**

**The one truly defensible hook:** a **hosted, tamper-evident audit log** of the verify pipeline — every AI claim in a corpus, with proof it anchored to real source text, timestamped, retained, exportable, centrally controlled. The local CLI can *produce* verify results; what it cannot do by physics is be a *trusted shared system-of-record* that an auditor or opposing counsel accepts (you can't trust a log the annotator can rewrite locally). That is the only feature where DIY/self-host is genuinely worse than paying, and it maps to the only buyer with a budget line (compliance/legal/scientific review, landing/index.html:131-152).

**Solo-indie operational reality forces sequencing.** The `/ai/proxy` is not a billing concern — it is an unbounded same-day cash-loss concern: server-side provider keys billed to the founder's card, a stolen token running ai-batch over a 500-page corpus on net-30 terms before Paddle settles $10. "Meter in D1" is racy under parallel streaming. Therefore:
- **Launch Pro with the bounded, low-abuse features first** (encrypted sync, hosted permalink shortening, free export) — none can produce same-day cash loss.
- **Managed AI must be PREPAID-ONLY with a hard, atomic server ceiling** (conditional `UPDATE ... WHERE balance >= cost`, not read-then-decrement; per-token concurrency cap). Sell fixed credit packs; refuse with 402 at zero.
- **Decouple the web launch from Managed-AI risk:** ship a "web reader" tier with AI *disabled* first (anchoring/verifier/lineage/MarkRank/permalink all work with zero AI). Add Managed AI to web only after the prepaid proxy is battle-tested on desktop.
- **Do NOT launch Team/Enterprise as a solo dev.** Those buyers demand DPA, SLA, security questionnaire, likely SOC2 — unservicable by one person, a far bigger sink than code. Sell them self-serve Pro until there is a second human or a paying design partner.
- **Validate first.** The entire revenue thesis rests on one unvalidated assumption — that compliance/legal buyers will pay $25-40/seat for a shared tamper-evident audit-of-AI-claims log. Take that pitch to 5-10 of the named personas *before* building the Worker/D1/Paddle/WorkOS stack.

## 5. Concrete pricing proposal

**FREE — "Marklee Local"** · $0, forever, MIT.
Everything in the app today: all 13 themes, unlimited local annotations, JSON sidecars, lineage graph, MarkRank, **BYO-key AI** (Anthropic/OpenAI/Gemini/Ollama), the full CLI (summary/annotate/ai-batch including local verify), self-contained local permalinks, **and ISO-32000 PDF export** (moved here deliberately — it's server-less, one-time-value, and free export defuses lock-in fear). The free app never contacts a server.

**PRO — "Marklee Sync"** · **$6/mo or $60/yr.**
Priced as a thin convenience add-on, not a flagship. Encrypted cross-device sidecar sync (client-encrypted blobs — server sees ciphertext only; on-disk sidecars stay canonical, sync is a non-authoritative mirror), hosted short/vanity permalinks with revocation (`marklee.link/<id>`), and **prepaid Managed-AI credit packs** for users who don't want to BYO-key (hard server ceiling, never postpaid). Managed AI is also the *only* AI path on the web build.

**TEAM / AUDIT — "Marklee Audit"** · **$30/seat/mo** (validate first).
The real moat: shared team workspaces, **hosted tamper-evident audit log** of the verify pipeline (every AI claim + proof of anchoring, timestamped, retained, exportable for regulators/opposing counsel), SSO (SAML/OIDC + SCIM), pooled admin-controlled AI credits, private permalink namespace. **Do not build until validated and until there is a second human to carry compliance load.**

**Payments:** **Paddle** (merchant-of-record) for self-serve Pro — *because a solo founder cannot register for VAT/sales-tax in ~40 jurisdictions; MoR makes the platform the legal seller and absorbs tax + chargeback liability for ~5% vs Stripe's ~2.9%, which is the 2% you happily pay to not have a compliance department.* Reserve raw **Stripe Billing** for Team only (invoicing/PO/ACH justify the tax overhead at that deal size).

**Auth/SSO:** **License-token, no account, for Pro** — *because it's identical in shape to the BYO-API-key flow users already accept (secrets.rs), so it preserves "no account" exactly and needs no auth server to run.* **WorkOS** for Team SSO — *because it's purpose-built to sell enterprise SAML/SCIM as a feature, bills per-connection (you pay only when you land a deal), and building SAML yourself is a solo-dev grave.* Ship the Ed25519 license key with a key-ID and accept 2 keys from day one (the embedded public key can never be rotated otherwise without bricking every install).

**Minimal server footprint:** one **Cloudflare Worker + D1 (SQLite) + R2 (blobs)** — the landing page already deploys to Cloudflare Pages (scripts/build-landing.mjs:189-220), so the toolchain exists. Endpoints: `/webhook/paddle` (mint/revoke license), `/sync/:id` (R2, ciphertext), `/link/:id` (permalink render), `/entitlements` (D1 status), and later `/ai/proxy` (prepaid-capped, atomic balance check). The renderer change is one new "managed" provider in `providers.js` whose base URL is the Worker and whose key is the license token.

## 6. Risks & what NOT to do

- **Do NOT ship any paid endpoint before the brand-line rewrite and zero-telemetry commitment go live.** Silently breaking the 6× "no server, ever" promise reads as betrayal to the exact audience you depend on. Enforce zero-phone-home via a minimal CSP allowlist, not just intent.
- **Do NOT sell ISO-32000 export as a subscription.** It's server-less and one-time-value; paywalling users out of their own data poisons trust with the privacy buyer. Free it.
- **Do NOT lead Pro with Managed AI.** You'd be asking your most technical, BYO-key-capable users to adopt a more expensive, less-private path. Keep it as a web-build necessity and a prepaid convenience, never the flagship.
- **Do NOT run Managed AI postpaid or with naive D1 metering.** A stolen token + ai-batch over a large corpus is unbounded same-day loss on the founder's card; D1 read-then-decrement races under parallel streaming. Prepaid + atomic conditional decrement + concurrency cap, or don't ship it.
- **Do NOT launch Team/Enterprise solo.** DPA/SLA/security-questionnaire/SOC2 load from legal buyers will sink a one-person shop faster than any code.
- **Do NOT start the `main.js` decomposition before adding `jsconfig`/ESLint and a smoke-test seam.** Refactoring a 7091-line monolith with ~25 globals and no type help or tests is how you ship silent regressions. Sequence the safety net first.
- **Do NOT overstate hosted permalinks.** The local URL payload (marklee-permalink.js:30-60) already resolves for someone without the file. Hosting adds only shortening + revocation — say so.
- **Do NOT let the lineage-graph redesign run before `colors.js` lands** — it would inherit map-view.js:190's wrong palette. Sequence color unification first.
- **Do NOT cross from "crafted" into "busy/kitsch."** The steampunk/popshow themes already flirt with it. Hold the line: motion is feedback, not decoration; every infinite loop must justify itself and must die under `prefers-reduced-motion`. `mix-blend-mode: multiply` on highlights assumes a light page — gate it on theme luminance.
- **Do NOT block web/desktop launch on mobile.** It's an XL track with desktop-bound native deps; treat it as separate and later.
